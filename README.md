# Jeda Assistant (제다 어시스턴트)

Discord 서버 채널·스레드에서 봇을 직접 멘션해 문서와 이미지를 분석하고, 웹 자료를 조회하거나 대화를 이어간다. 답장으로 다른 사람의 메시지를 지목할 수 있다. 요청과 결과는 요청자별로 관리한다. 로컬 HTTP 서버와 Discord가 같은 라우터, 도구, SQLite 저장소 구현을 사용한다.

## 설치와 설정

Python 3.12 이상에서 프로젝트를 설치한다.

```sh
python -m pip install -e '.[dev]'
```

`.env.example`의 항목을 검토해 프로젝트의 `.env`에 설정한다. 모델 API 키는 `OPENAI_API_KEY`, Discord 로그인은 `DISCORD_TOKEN`이다. 기존 봇의 DB를 가리키지 않도록 `JEDA_DATABASE_PATH`를 사용한다. 기본 경로는 `./data/jeda.sqlite`다. 개편판이 인식하지 못하는 테이블이 있는 기존 DB는 열기를 중단한다. 모델 이름과 시간·용량 한도는 설정 파일에서 조정할 수 있다.

## 실행 경로

### 로컬 상태 관리창

Discord 봇을 시작한 뒤 같은 PC의 브라우저에서 [제다 상태 관리창](http://127.0.0.1:8766/)을 연다.
봇이 관리창을 함께 실행하고 종료한다. 관리창은 IPv4 루프백에만 바인딩되며 운영 DB를 읽기 전용으로 조회한다.

- **개요**에서 Discord 연결 상태, 최근 요청·오류, 진행 중인 작업 수를 확인한다.
- **대화**에서 사용자 → 서버 → 채널을 선택하거나 전체 원문을 검색한다. 요청 상세에서 도구 근거, 모델 호출, 정정, 답변 전송 기록을 확인한다.
- **메모리**에서 사용자 공통 및 채널별 메모리의 값, 보관된 이전 버전, 변경을 요청한 원문을 확인한다.
- **통계**는 한국 시간의 시간·일·주(월요일 시작)·월 기준으로 사용자 요청과 실제 모델 호출을 각각 집계한다. 호출 수집을 시작하기 전 기록과 API가 제공하지 않은 토큰 값은 대시로 표시한다.

과거 요청에 Discord 이름이 없으면 같은 ID에서 확인된 이름 또는 ID를 표시한다. 이전 버전에서 저장하지 않은 메모리 삭제·복구 이력과 모델 호출은 소급 생성하지 않는다.

### 봇과 검증 서버

Windows에서는 Python 3.12 이상과 `.env`를 준비한 뒤 프로젝트 폴더의 `start-bot.bat`를 더블클릭한다. 첫 실행 시 전용 가상환경(`.venv`)을 만들고 필요한 패키지를 자동으로 설치하므로 인터넷 연결이 필요하다. 봇을 사용하는 동안 실행 창을 열어 두고, 종료하려면 창에서 Ctrl+C를 누른다.

| 명령 | 용도 |
| --- | --- |
| `assistant-bot` | Discord에 연결한다. Discord 설정에서 Message Content Intent를 켜고, 사용할 채널의 메시지 조회·기록 읽기·답장 권한을 부여한다. 실제 표시 이름은 Discord 앱/서버의 봇 프로필에서 설정한다. |
| `jeda-server` | 실제 모델과 연결되는 로컬 검증 서버를 127.0.0.1:8765에서 연다. 설정 경로 옆의 별도 .local DB를 사용한다. 로컬에서 Discord 첨부 삭제·재시작을 재현하는 자료와 전송 기록은 검증 DB 옆의 .transport 파일에 저장한다. 이 서버는 신뢰할 수 있는 로컬 개발자 전용이다. |
| `assistant-admin ask "질문"` | 같은 엔진으로 터미널에서 질문한다. |
| `assistant-admin doctor` | 비밀값을 표시하지 않고 설정 여부를 점검한다. |
| `assistant-admin stats` · `assistant-admin backup --output backup.sqlite` | 운영 DB 건수 조회와 별도 파일 백업. |

## 사용 예시

- 본인 또는 다른 사용자의 게시물에 답장하면서 `@제다 이 내용의 공식 출처를 찾아줘`라고 한다. 삭제된 원문은 다시 요청한다.
- PDF와 함께 `@제다 4장의 그림과 핵심 결론을 요약해줘`라고 한다. 진행 중 `@제다 표로 바꿔줘`로 정정할 수 있다.
- `@제다 이 견적서 기억해줘`는 문서 참조를 저장한다. 파일 원본은 Discord에서 다시 읽으며 삭제되면 재첨부를 요청한다.
- `@제다 이 채널의 내 메모리 전부 삭제해줘`는 승인 대기 상태가 된다. 출력된 문구로 같은 채널에서 직접 멘션해 승인하거나 취소한다.
- 대화 원문 기록은 백엔드가 추가하고 모델에는 읽기 도구만 제공한다. 세션 초기화와 장기 메모리 삭제는 원문을 지우지 않는다.

## 문서 판독 범위

소스 코드·설정·패치 파일(`.py .js .ts .tsx .java .c .cpp .h .go .rs .sql .sh .toml .diff .patch`)은 실행 없이 원본 줄 번호와 들여쓰기를 읽는다. SRT·VTT 자막은 시간 구간으로, ODP 발표 자료는 슬라이드 번호로 참조한다. HEIC·HEIF 사진은 기존 이미지 분석 경로에서 읽는다.

HWPX와 최신 Office 형식은 지원한다. 구형 HWP·DOC·XLS·PPT 등 미지원 형식은 파일명을 명시해 안내하고, 같은 요청의 지원 파일은 계속 처리한다.

여러 페이지의 TIFF와 애니메이션 이미지는 프레임 위치를 붙여 읽는다. 한 요청에서 최대 16프레임을 확인하고, 남은 프레임은 범위를 지정해 요청할 수 있다. PPTX는 그룹 안의 도형과 발표자 노트까지 슬라이드 번호에 연결한다. CSV·TSV는 UTF-8, CP949, BOM이 있는 UTF-16을 지원한다.

PDF의 장 범위는 북마크와 본문 제목을 대조한다. 스캔본에서 제목 위치를 찾는 로컬 OCR은 Tesseract 한국어·영어 데이터가 있을 때 사용한다. 범위가 모호하면 PDF 쪽수를 묻고, 이미지·스캔·벡터가 있는 선택 페이지는 시각 모델로 읽는다. 한 번의 PDF 판독 범위는 최대 80쪽이며 이후 쪽은 미확인 범위로 전달한다.

문서 소개는 첫 3쪽에서 주제를 확인하고 필요하면 뒤쪽을 읽는다. 전체 요약은 지정 범위 끝까지 읽는다. 일반 슬라이드·스캔은 최대 8쪽씩 묶어 두 요청까지 동시에 판독한다. 표 전체 전사는 원본 텍스트의 열 정렬을 활용하고, 스캔 표는 행 구간별로 읽어 누락을 확인한다.

시트는 저장된 셀 값과 수식 캐시를 구분한다. 캐시가 없는 수식은 계산값 미확인으로 처리한다.
